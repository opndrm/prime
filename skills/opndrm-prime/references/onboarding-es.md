# Incorporación de Open Dream Prime — Español

Usa esta secuencia con una persona nueva del equipo.

1. Pregunta qué espacio necesita: OPNDRM APP para un proyecto nuevo, ADAM o FRNKLY.ONE.
2. Indícale que use el instalador de opndrm.com. En una Mac sin herramientas de línea de comandos de Apple, abre directamente Actualización de software. Si Apple requiere primero una actualización de macOS, complétala, reinicia si se solicita y ejecuta otra vez el mismo comando de OPNDRM; si no, instala las herramientas y la Terminal original continúa. En Windows, aclara que el instalador es una vista previa para el primer equipo. Si falta Windows App Installer, abre Microsoft Store y la persona ejecuta el mismo comando otra vez después de instalar el requisito. El instalador oficial de Buzz aparece en su propia ventana visible. Para ADAM o FRNKLY.ONE, GitHub CLI —no una acción separada del navegador— realiza una sola autorización personal por dispositivo antes del clon: la persona inicia sesión con su propia cuenta de GitHub e ingresa el código de un solo uso únicamente en la página oficial de dispositivos de GitHub. No se usa un inicio de sesión, token, credencial compartida de Open Dream ni acceso de administrador del repositorio de GitHub. El instalador muestra el nombre de usuario autenticado y comprueba el acceso de lectura al repositorio privado antes de clonar. Si falta acceso, el propietario del repositorio debe invitar esa cuenta personal como colaborador normal con el acceso necesario; FRNKLY.ONE siempre requiere esa invitación. FRNKLY.ONE es la reconstrucción en Rust en `https://github.com/opndrm/Frnkly.one.git`; su lane local sigue siendo FRNKLY.ONE. OPNDRM APP nunca abre la autorización de dispositivos de GitHub.
3. Confirma que su checkout es propio y que no sobrescribió otro proyecto.
4. El instalador crea o reutiliza la sesión HERDR personal correspondiente solo después de que exista la raíz seleccionada y después abre WezTerm conectado a `opndrm-opndrm-app`, `opndrm-adam` u `opndrm-frnkly-one`. Se detiene sin mostrar Ready si esa sesión no puede iniciar o conectarse.
5. Explica los roles visibles: PRIME construye; `NO MISTAKES GATE — RESERVED (INACTIVE)` permanece inactivo; Buzz es la conversación; Wayfinder es el plan del Issue de GitHub; GitHub es el registro del código.
6. El instalador prepara y abre el registro local de incorporación a Buzz de esa persona en el contexto del espacio seleccionado con un agente PRIME sugerido. Permanece esperando el propio inicio de sesión de Buzz de la persona; después crea o conecta el agente y guarda su identificador aprobado en su propia entrada OPNDRM de Atomic Vault.
7. La persona debe completar por sí misma el inicio de sesión y el paso de confianza de Atomic Vault. No manejes ni solicites sus credenciales.
8. Inicia la primera tarea desde un Issue de Wayfinder. Indica resultado, alcance, comprobación de calidad y condición para detenerse.

Si la instalación se detiene, informa el bloqueo en lenguaje claro. Nunca pidas contraseñas, tokens, códigos de recuperación ni claves privadas.
